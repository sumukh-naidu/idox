## 4. The model setup

- **Default model: Qwen3-VL-4B (Q4_K_M) on the GPU** (Quadro RTX 3000, 6 GB), through `llama-server` (CUDA build b11247),
  port 8090. About 5.3 GB of VRAM, about 55 tokens per second. The 2B CPU model still works (about 18 tokens per second).
- **Run one server only.** Two copies at once used too much memory and caused a surge.
- Start command (the paths contain spaces, so each path is quoted):

```powershell
& "$env:USERPROFILE\.local\opt\llama.cpp\llama-b11247-cuda12\llama-server.exe" --model "D:/AI Models/Qwen3-VL-4B/Qwen3VL-4B-Instruct-Q4_K_M.gguf" --mmproj "D:/AI Models/Qwen3-VL-4B/mmproj-Qwen3VL-4B-Instruct-F16.gguf" --port 8090 --host 127.0.0.1 --no-webui --ctx-size 8192 --image-min-tokens 512 --image-max-tokens 512 --parallel 1 --device CUDA0 -ngl 99
```

- **The prompt.** The page prompt now makes the model count its blocks and not stop early (`blocks.py`). On the dense test
  pages it raised the share of words found from 86-91% (old prompt) to 97-99%. On a picture shorter than 1400 px the plain
  prompt is used instead: the page prompt made the model skip centred titles and the heading above a table.
- **How a page is read.** A model of 3 billion parameters or more (the server reports its size) reads a full page in one go;
  the 2B keeps its two-strip reading, which is what raised its recall. `IDOX_SPLIT` overrides this for a test.
- **The 35B model** (Qwen3.6-35B-A3B) is better at reading (page 1 of the dense test: 99% against the 4B's 97%) but not
  usable here: about 4 minutes per page and 17 GB of the 31.6 GB RAM, so it was stopped before it could cause a surge.

## 5. Fixes made in this period

| Fix | What was wrong | Where |
|---|---|---|
| PowerPoint titles | A centred textbox left the real title placeholder empty (3 tests failed). The placeholder is now kept, full width and centred, and sits at the top of the slide | `to_pptx.py` |
| Duplicated table | When the model wrote a table as prose, the table was restored from the PDF as well. It is skipped now if its words are already on the page | `test_pdf.py` |
| Dropped table column | The model read 4 of 5 columns; the row repair then appended every row a second time. The table is rebuilt from the PDF's grid | `test_pdf.py` |
| Table pairing | Model tables were paired with PDF tables by order, which went wrong with a nested table. They are paired by shared cells | `test_pdf.py` |
| `csv_plan.py` | Dropped the first row when the file had no header; added a made-up title. Added `--no-title` and keeps every row | `csv_plan.py` |
| Control characters | A form feed in a PDF's text made the whole Word build fall back to default styles. Text is cleaned before writing | `to_docx.py` |
| Footer first | A PDF that stores its footer first pushed every page of the Word file onto a blank one (4 pages became 8). Header and footer lines are moved to their ends | `pdf_look.py` |
| Excel prose | A title and paragraph shared one unwrapped cell. Prose cells wrap now | `to_xlsx.py` |
| Output folders | `test_pdf.py` crashed at the end if the output folder did not exist. It creates the folder now | `test_pdf.py` |
| Text encoding | Some text files were written without an explicit encoding. They are UTF-8 now | several |
| Windows | A LibreOffice profile path, absolute paths and the `soffice` location | `image_to_pdf.py` and others |

## 6. How tables keep their look

- **PDF and Word sources.** The PDF's own text layer and drawings give the truth: the alignment of each column (left,
  centre, right), the header's fill colour and the column widths are measured (`pdf_look.py`) and written by the Word,
  PowerPoint and Excel writers. Checked by eye on a 4-page PDF with a navy header, numeric columns, three tables on one
  page and a nested table: the Word output matched the original apart from small spacing differences.
- **Pictures with ruled tables.** `image_look.py` finds the table's row and column lines in the picture, then reads the
  header fill and each column's alignment from the pixels. No text is read, so no OCR is involved. A table whose grid does
  not fit what the model returned is left as it is.
- **Pictures with faint or no column lines** keep the default look. A test of a rule for them (gaps in the text plus
  which edge lines up) got only 2 of 5 data columns right, so it was not built. A wrong alignment is worse than none.

## 8. Known limits and open items

| Item | Detail |
|---|---|
| Repeated paragraphs, page-prompt threshold, PowerPoint table rows, merged titles | **Fixed on 2026-10-19**, see `docs/tweaks_and_work_summary_2026-10-19.md` |
| Picture reading | Small pictures reach 83-92% of the expected phrases; the model sometimes drops a heading (for example the one above a table) or misreads a word. A bigger model helps (35B) but is too slow here. A higher image budget fixed one picture and hurt another, so it was not adopted |
| Alignment from faint or borderless pictures | Not measured reliably (section 6). Fixing it would mean asking the model for alignment, which changes its output format and needs its own test |
| Nested tables | The content is kept but flattened into the outer table |
| Broken PDF characters | Where the PDF's text layer stores a symbol as a replacement character, it cannot be recovered; the line stays short |
| API and web app | The ten new conversions are command-line only. The API and web app were not run with the model |
| Housekeeping | `docs/implementation_summary.pdf` is out of date; loose files at the project root (`extracted.md`, `my_output.csv`, `status*.md`, `handover*.md`, `sample_englishl.*`) are not organised |
